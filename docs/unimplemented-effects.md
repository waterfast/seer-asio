# 现有核心表达不了 / 表达式不干净的技能效果

本文记录 standard/wang 包（王·雷伊、王·盖亚）落地时，**能不别扭地实现**与**不能**的边界。
判定原则来自用户要求："宁可少做也不要 hack"：技能定义照做（id / 类型 / 属性 / 威力 / PP /
先制 / 命中率 / desc 照抄 wiki 原文），够不着的效果就留空或只做能拆出来的那部分，
在这里逐条写清"原文 → 为什么不行 → 核心要补什么"。

- 技能定义：[`packages/seer-core/standard/wang/skills.lua`](../packages/seer-core/standard/wang/skills.lua)
- 效果实现：[`packages/seer-core/standard/wang/effects.lua`](../packages/seer-core/standard/wang/effects.lua)
- 数据来源：biligame 技能页原文 `https://wiki.biligame.com/seer/index.php?title=技能:<ID>&action=raw`
  （抓取与双向核对另见 `docs/skill-research.md`）

## 二、完全未实现

### 1. 寰宇雷神断（19733，物理/电/150/PP5/95%）

- 原文：**50%使对手麻痹，自身每处于一种能力提升状态则概率提高8%**
- 为什么表达不了：核心**没有异常状态系统**。麻痹不是能力等级也不是伤害数值，
  它需要"精灵身上的状态标记 + 命中/出手环节查询 + 回合递减"，现有 `Effect` 只能在
  已注册的 timing 上改 `data`（伤害、暴击率）或调能力等级，没有任何钩子能挂上一个
  "持续若干回合的状态"。按概率触发本身没问题（`ctx.logic.rng` 可用），缺的是状态本身。
- 需要核心补：**异常/控制状态系统**（登记状态类型、挂到 pet、影响出手与命中、
  按回合递减与清除），外加"免疫异常状态"的查询入口。
- 现状：技能定义照做，`effects = {}`，`extra.unimplemented` 已标注。

### 2. 王·联盟审判[追加]（30122，物理/普通/350/PP1/必中）

- 原文：**对大暗黑天长老造成的伤害提高50%；35%概率使对手陷入麻痹状态2回合**
- 为什么表达不了：
  1. "对大暗黑天长老"要求按**目标种族/分类**判定。核心的伤害时机里只有 `data.target`
     这个 Pet 对象，没有任何"目标分类钩子"（标签、阵营、种族集合）；也没有大暗黑天
     长老这个种族数据。写死一个名字判断既不是通用规则，也无从验证。
  2. 概率麻痹同第 1 条，需要异常状态系统。
- 需要核心补：**目标/阵营分类钩子**（如技能 tags + pet tags 的匹配），以及异常状态系统。
- 现状：`effects = {}`。

### 3. 极度冲刺（30156，特殊/战斗/140/PP5/必中）

- 原文：**反转自身能力下降状态**
- 为什么表达不了：`BattleRoom` 只有 `changeStatStages`、`clearPositiveStatStages`、
  `clearNegativeStatStages` 三个写入入口，"反转"（负变正、正变负）**没有实现**。
  `core/events/stat_stage.lua` 已经定义了 `operation = "reverse"` 的数据契约
  （`changes` 为目标等级的相反数减原等级），注释里也写明"本次不提供 Room 反转函数"。
  用 `changeStatStages` 逐个塞 `-2×等级` 的增量虽然结果数值相同，但会走成多次普通
  能力变化、发 `operation = "change"` 的通知，语义和时机（`Before/AfterStatStagesReverse`）
  全错，属于"硬凑"。
- 需要核心补：**`BattleRoom:reverseStatStages(target, source, reason)`**，实现已定义好的
  `reverse` 操作并复用 `Before/AfterStatStagesReverse` 时机。
- 现状：`effects = {}`。

### 4. 威斗天罡破（30157）——前半段

- 原文：**对手处于能力下降状态时自身先制+1**（后半段增伤已实现）
- 为什么表达不了：出手顺序在 `GameLogic:doRound` 里**先排序、后触发 `DecidePriority`**：
  `actions` 按 `skill:getPriority()` → 速度 → 座位排完之后才发 `DecidePriority`，
  此时顺序已经定死，效果再改 `data.order` 也不会重新排序。而且"先制+1"是技能级
  属性，不是持久状态，需要排序前对每个 action 的动态先制修正。
- 需要核心补：**排序前的先制修正钩子**（例如把 `DecidePriority` 拆成
  "收集先制修正 → 排序 → 公布顺序"，或提供一个可在排序前修改 `actions` 的时机）。
- 现状：技能 `effects` 只挂增伤效果；本段写入 `extra.unimplemented`。

### 5. 天威力破（30155）——前半段

- 原文：**消除对手回合类效果，消除成功则己方免疫下1次受到的异常状态**
  （后半段"伤害不足 280 则下 2 回合必致命"已实现）
- 为什么表达不了：
  1. "回合类效果"是一整类在场效果，核心**没有回合类效果注册表**，也没有"清除对手
     某种分类效果"的接口：`room` 只有 `clearPositiveStatStages` 一类能力等级操作。
  2. "消除成功才免疫下 1 次异常"还依赖异常状态系统（见第 1 条）。
- 需要核心补：**在场效果分类与清除接口**（回合类效果的登记、查询、按来源/拥有者清除），
  以及异常状态系统。

### 6. 王·联盟审判[追加]（30185）——前半段

- 原文：**对大暗黑天长老造成的伤害提高50%**（后半段"伤害不足 300 则下次 +100%"已实现）
- 为什么表达不了：同第 2 条第 1 点，缺少目标分类钩子；且"大暗黑天长老"这个分类本身
  在核心与图鉴数据里都不存在，无法核实，不能把名字写死。
- 需要核心补：目标/阵营分类钩子。

## 三、用"局内临时状态"模拟实现（核心没有原生机制，但按仓库既有模式做了）

这三条不是"表达不了"，而是**核心缺少原生系统、当前用 pet 字段 + 常驻 Effect 模拟**。
模式与 `standard/effects/thunder_awakening.lua` 一致：状态写在 pet 上（`wang_` 前缀），
Effect 定义保持无状态，用完或过期由效果自己摘除。将来核心补了原生系统，应迁移过去。

### 金翼剑轮（19731）——免疫下 1 次受到的攻击

- 实现：命中时给使用者挂 `wang_immune_attacks = 1` 与一个常驻 Effect；下一次受到的攻击在
  `BeforeAttack` 被整体取消（多段攻击只消耗一次），随后计数清零、效果摘掉；额外发一条
  `AttackImmune` 通知，便于测试与 UI 观察。
- 模拟的边界：计数在 pet 上、不参与"效果分类"，**无法被"消除对手回合类效果""驱散"之类
  的机制处理**，也不会随换人/下场统一清理（当前战斗模型没有换人）；效果之间也无法叠加成
  多层护盾。
- 需要核心补：**原生"免疫次数 / 护盾 / 抵挡"系统**（可分类、可清除、可叠加、可过期）。

### 天威力破（30155）——下 2 回合的攻击必定致命一击

- 实现：`Attack` 时机（扣血后）判定本次实际伤害 < 280 时，给使用者挂
  `wang_crit_guarantee = { logic, start_round, expires_after_round }` 与两个常驻 Effect；
  后续两个回合的 `CriticalChanceCalculate` 把 `crit_chance` 抬到 100，`TurnEnd` 到时清理。
- 边界：状态挂在 pet 上，换人/驱动类机制无法识别；"回合"直接读 `logic.round`，
  当前核心是单回合制模型，够用。

### 王·联盟审判[追加]（30185）——下 1 次攻击伤害 +100%

- 实现：一次性的 `wang_damage_double` 标记 + 常驻 Effect，下一次自己造成的有效伤害
  在 `AfterDamageCalculate` 翻倍后立刻消耗。
- 边界：多段攻击只翻第一击；"攻击"的定语（是否区分物理/特殊、是否包括固定伤害）原文
  没有细化，这里按"下一次造成伤害的攻击"处理。

## 四、参考技能（不占四格，未挂到精灵上）

按 Lead 对原始技能串的判定，"最后学会的四个主要技能"= 最后三个普通技能 + 追加技能；
以下条目不进四格，因此没有挂载，只在此登记，避免以后重复踩坑。

### 万鸣齐闪（24970，属性/普通/PP5/先制3/必中）

- 原文：**反转自身能力下降状态；直接造成260点电系伤害，自身每处于一种能力提升状态则造成的伤害提高10%**
- "反转"同第二节第 3 条（无入口）。
- "直接造成 260 点电系伤害"可以用 `logic:changeHp` 直接做，但它是"技能结算里的一次
  固定伤害"，不属于攻击/伤害链，会绕过暴击、克制与伤害时机；当前核心没有"技能直接
  造成伤害"的结算入口（`changeHp` 是底层写血方法，不是规则层语义），要做得干净需要
  核心补一个规则层的 `logic:dealFixedDamage(target, num, element, reason)`。
- "每处于一种能力提升状态 +10%"需要"提升状态"计数（正等级总和），当前核心同样没有查询。

### 战神狂怒（24120，属性/普通/PP5/必中）

- 原文（wiki 数据由调研 agent 交叉核对，本仓库未挂载）：攻击/防御/特攻/特防/速度/命中
  各 +1；下 3 回合能力提升状态消失则对手使用属性技能失效；4 回合内免疫所有受到的异常
  状态；3 回合内每回合攻击 +1。
- 涉及能力等级操作（可做）+ 回合类效果监听（"能力提升状态消失"的触发）+ 技能失效控制 +
  免疫异常 + 回合内持续强化，后四样都需要回合类效果注册表与异常状态系统，见下方汇总。
